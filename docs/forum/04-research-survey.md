### 1b. Auth/SSO, API, embedding, moderation, SEO, mobile, export, upgrades

**Discourse**
- SSO consumer without OIDC: yes — **DiscourseConnect**: your site signs a Base64 query-string payload with HMAC-SHA256 over a shared secret; required `nonce`, `email` (must be verified), `external_id`; optional `username`, `name`, `avatar_url`, `avatar_force_update`, `groups`, `admin`, `moderator`, `require_activation`, `suppress_welcome_message`; "It doesn't use a standard protocol" ([meta 13045](https://meta.discourse.org/t/setup-discourseconnect-official-single-sign-on-for-discourse-sso/13045), last edited May 27 2026). Server-side `POST /admin/users/sync_sso` pushes profile changes without a login; `POST /admin/users/{id}/log_out`. Official OAuth2/OIDC plugins also exist (not needed here). Cookie/JWT session sharing: no.
- REST API (from [docs.discourse.org openapi.json](https://docs.discourse.org/)): `POST /users.json`, `PUT /admin/users/{id}/suspend|silence|deactivate|anonymize.json`, `DELETE /admin/users/{id}.json`, `GET /latest.json`, `GET /c/{slug}/{id}.json`, `GET /t/external_id/{external_id}.json`. Auth by `Api-Key` + `Api-Username` headers.
- Embedding: comments-on-external-page via `embed.js` iframe (read-only; reply happens on the forum; auto-creates a topic per URL) ([meta 31963](https://meta.discourse.org/t/embed-discourse-comments-on-another-website-via-javascript/31963), updated May 2024); topic-list widget `embed-topics.js` with `<d-topics-list>` filtered by category/tags ([meta 125911](https://meta.discourse.org/t/embedding-a-list-of-discourse-topics-in-another-site/125911)).
- Moderation: trust levels TL0–TL4 ([blog](https://blog.discourse.org/2018/06/understanding-discourse-trust-levels/)), flags/review queue, rate limits, IP blocks, official Akismet plugin (pushed Aug 26 2026, [repo](https://github.com/discourse/discourse-akismet)), user anonymize, self-service data export from Preferences ([meta 313677](https://meta.discourse.org/t/export-user-data/313677)); self-delete only for accounts without post history, otherwise by request ([meta 278348](https://meta.discourse.org/t/how-to-always-allow-users-to-delete-their-own-accounts/278348)).
- SEO: serves a separate simplified HTML view to crawlers (see [meta 226554](https://meta.discourse.org/t/disable-or-bypass-feature-detect-for-googlebot-while-serving-js-app-to-crawlers/226554)); site settings `allowed crawler user agents` / `blocked crawler user agents` / `slow down crawler user agents` ([meta 62431](https://meta.discourse.org/t/how-to-block-all-crawlers-but-googles/62431)). No AI-bot-specific preset found **[unverified]**.
- Mobile: responsive; installable PWA with push on iOS ([meta 146346](https://meta.discourse.org/t/discourse-now-works-as-a-pwa-in-ios/146346)); DiscourseHub app on both stores ([discourse.org/app](https://www.discourse.org/app)).
- Export/import: full backups = SQL dump + uploads tarball, restorable on any Discourse ([meta 122710](https://meta.discourse.org/t/create-download-and-restore-a-backup-of-your-discourse-database/122710)); ~70 importers in `script/import_scripts` incl. phpbb3, mybb, nodebb, flarum_import, vanilla, xenforo, vbulletin, question2answer, disqus, csv_importer, json_generic. Exit path to other software: DB dump + third-party tools only.
- Upgrades: monthly; `./launcher rebuild app` = several minutes of downtime; the April 2025 rebuild memory spike (~3.1 GB peak) was reduced to ~1.6 GB after a fix on Apr 4 2025, with 2–4 GB swap still advised ([meta 360419](https://meta.discourse.org/t/high-rebuild-memory-requirements-april-2025-edition/360419)).

**Flarum**
- SSO: nothing in core. Community extensions: `clarkwinkelmann/flarum-ext-jwt-cookie-login` (stateless JWT cookie set by your app, auto-creates users; pushed Jun 11 2026, [repo](https://github.com/clarkwinkelmann/flarum-ext-jwt-cookie-login)), `maicol07/flarum-ext-sso` (pushed May 23 2026, [repo](https://github.com/maicol07/flarum-ext-sso)), `maicol07/flarum-oidc-client` (needs OIDC). None official; 2.0 compatibility per-extension **[unverified]**.
- API: JSON:API; `POST /api/users`, `GET /api/discussions`; "API Keys must be manually created in the database (no UI)"; docs "still in progress" ([REST docs](https://docs.flarum.org/rest-api/)).
- Embedding: none found **[unverified]**.
- Moderation: bundled flags/suspend/approval/Akismet extensions **[not individually verified]**.
- SEO: SPA; `fof/seo` adds meta/OG/schema.org `DiscussionForumPosting` and `fof/sitemap` adds sitemap/robots ([fof/seo README](https://github.com/FriendsOfFlarum/seo)).
- Mobile: responsive; no official app. Export: DB dump; Discourse has a `flarum_import` script as an exit path. Upgrades: Composer; 1.x→2.0 breaks extensions ([update guide](https://docs.flarum.org/2.x/update/)).

**NodeBB**
- SSO without OIDC: yes — `nodebb-plugin-session-sharing` reads a JWT from a cookie on the naked domain (e.g. `.makapix.club`), verifies it with a shared secret, needs `id` + `username` claims (optional `email`, `picture`), auto-creates and syncs users ([repo](https://github.com/julianlam/nodebb-plugin-session-sharing), by co-founder julianlam, pushed Aug 20 2026). Fits an HS256 JWT cookie issued by the site. Official `nodebb-plugin-sso-oauth2-multiple` (pushed Sep 15 2026) needs an OAuth2 provider.
- Write API ([write.yaml](https://github.com/NodeBB/NodeBB/blob/master/public/openapi/write.yaml)): `POST /users`, `PUT /users/{uid}`, `/users/{uid}/picture`, `/users/{uid}/ban`, `/users/{uid}/mute`, `DELETE /users/{uid}/account`, `/users/{uid}/exports/{type}` (GDPR export); Read API `GET /api/recent`, `/api/category/{cid}`. Bearer tokens.
- Embedding: a `nodebb-plugin-blog-comments` existed; the NodeBB-org repo now returns nothing **[unverified/possibly moved]**.
- SEO: content available in `<noscript>` for crawlers per an old community thread ([thread 285](https://community.nodebb.org/topic/285/seo)); date old **[weak source]**. Mobile: responsive, no official app.
- Upgrades: `./nodebb upgrade` per release; releases every 1–2 weeks (see 1a); ActivityPub federation is core in v4 (extra moderation surface).

**phpBB / MyBB**: built-in OAuth login only (needs an OAuth provider) — no signed-payload SSO, no REST API in core, no embedding; server-rendered PHP so SEO is straightforward; export = DB dump; Discourse ships `phpbb3` and `mybb` importers. Security releases are infrequent but each bundles many fixes (MyBB 1.8.41: 24 vulns).

**Misago**: built-in generic **OAuth2 client** with JSON-path mapping for user id/name/email (needs an OAuth2 authorization + userinfo endpoint on your side, not full OIDC) ([Authelia guide](https://misago-project.org/t/authelia-oauth-2-guide/1164/), [Django OAuth Toolkit thread](https://misago-project.org/t/integrating-with-django-oauth-toolkit/1257/)). No documented admin REST API **[unverified]**; no embedding. Thread pages are React in 0.39 (SEO **[unverified]**). Risk: 0.40 rewrite in flight, one maintainer.

**Apache Answer**: connectors `connector-basic` (OAuth2), `connector-github`, `connector-google`, `connector-apache` in [answer-plugins](https://github.com/apache/answer-plugins); "no support for external authentication out of the box, and plugins can only be used by making a custom build" ([issue 1353](https://github.com/apache/answer/issues/1353)). Swagger API at `/docs/api` ([docs](https://answer.apache.org/docs/api)). `reviewer-akismet` plugin exists. Q&A model, not discussion threads.

**Lemmy**: OAuth login lands in **1.0** (still beta), merged Sep 18 2024 via [PR 4881](https://github.com/LemmyNet/lemmy/pull/4881) and requires an **OIDC-compliant** provider (userinfo endpoint). lemmy-ui is server-rendered. Federated moderation burden; pict-rs image storage.

**Talkyard**: SSO without OIDC: yes — `POST /-/v0/sso-upsert-user-generate-login-secret` with Basic-auth API secret (`ssoId`, verified email, username, avatarUrl) → redirect to `/-/v0/login-with-secret?oneTimeSecret=…` ([SSO API](https://forum.talkyard.io/-374/talkyard-single-sign-on-api), 2020/2021); OIDC also supported. Requires ElasticSearch (RAM-hungry) and a transactional email service.

**Zulip**: JWT login backend — `POST /accounts/login/jwt/` with a JWT whose payload has `email`, signed per `JWT_AUTH_KEYS` ([auth methods](https://zulip.readthedocs.io/en/stable/production/authentication-methods.html)); also OIDC, SAML, GitHub/Google/Apple. Web-public channels are readable logged-out but "do not yet support search engine indexing" ([help](https://zulip.com/help/public-access-option)) — poor for SEO/archival. First-class export/import; official iOS/Android/desktop apps.

## Section 3 — Running Discourse on the shared 8 GB VPS

- **RAM reality.** Per worker ~280 MB unicorn + 200 MB Sidekiq + 180 MB unicorn master; discourse-setup defaults to 4 unicorn workers and `db_shared_buffers` 2048 MB, both tunable down ([meta 170751](https://meta.discourse.org/t/how-much-ram-is-needed-to-host-discourse-along-with-other-services/170751), Nov 2020; [meta 274954](https://meta.discourse.org/t/limiting-the-number-of-unicorns-memory-usage-and-swapping/274954)). A poster co-hosting Discourse with nginx + a static site on 4 GB saw 90–95% utilisation. 2026 guides put the single container at ~1.4–1.8 GB idle ([hostscout 2026](https://hostscout.io/blog/self-hosting-discourse-on-vps-2026/)). With ~5 GB free on the VPS, budget ~2 GB steady state (2 workers, reduced shared buffers) plus 2–4 GB swap for rebuilds ([meta 360419](https://meta.discourse.org/t/high-rebuild-memory-requirements-april-2025-edition/360419)).
- **External PG 17 / Redis 7.** Use `templates/web_only.yml` (no bundled PG/Redis) with `DISCOURSE_DB_HOST`, `DISCOURSE_DB_NAME/USERNAME/PASSWORD`, `DISCOURSE_REDIS_HOST/PORT`, and put the container on the shared Docker network via `docker_args: ['--network …']` ([meta 283507](https://meta.discourse.org/t/using-discourse-with-external-postgresql-and-redis/283507)). This is community-supported only; the launcher's bundled PG template is what CDCK tests. Required PG extensions on your PG 17 and PG-17 compatibility **[unverified]**. Reusing the prod PG also couples Discourse's monthly migrations to your prod database.
- **Behind Caddy.** Comment out `web.ssl.template.yml` and `web.letsencrypt.ssl.template.yml`, either expose `"127.0.0.1:8880:80"` or join the `caddy_net` network and proxy to `app:80`; Discourse's own nginx stays inside the container ([meta 337656](https://meta.discourse.org/t/integrating-discourse-caddy-and-wordpress-with-docker-ports-for-reverse-proxy/337656), Nov 2024). Alternative: unix socket via [web.socketed.template.yml](https://github.com/discourse/discourse_docker/blob/main/templates/web.socketed.template.yml). Official guide: [Run other websites on the same machine as Discourse](https://meta.discourse.org/t/run-other-websites-on-the-same-machine-as-discourse/17247). Because caddy-docker-proxy routes by container labels, the launcher container would need labels passed through `docker_args` — inference, not documented.
- **Email.** SMTP is set by `DISCOURSE_SMTP_ADDRESS/PORT/USER_NAME/PASSWORD` in `app.yml`. Resend SMTP: host `smtp.resend.com`, ports 465/2465 (SMTPS) or 587/2587 (STARTTLS), username `resend`, password = API key, same rate limits as the API ([Resend docs](https://resend.com/docs/send-with-smtp)); no Discourse-specific Resend thread found. INSTALL-cloud.md (2026) now says "you can skip email configuration" and fall back to "Login via Discourse ID" — but DiscourseConnect flows and digests still need SMTP in practice.
- **Backups.** Built-in scheduled backups (SQL dump + uploads tarball) to local disk or S3 ([meta 14855](https://meta.discourse.org/t/configure-automatic-backups-for-discourse/14855)); self-hosters also restic `/var/discourse/shared/standalone/backups` off-box ([meta 148630](https://meta.discourse.org/t/best-practices-for-backups/148630)). The existing nightly restic job can include that path.
- **Other gotchas.** Rebuild downtime of minutes monthly; ESR lets you upgrade every ~6 months instead; 100 GHSA advisories Feb–Aug 2026 means you should not sit far behind.

## Section 4 — What "build your own" entails

Minimum 2026 feature set (union of what the products above ship in core): categories/tags; topics + replies with pagination and stable permalinks; Markdown editor with image upload, paste, oneboxes/link previews; @mentions; in-app + email notifications with per-topic/category subscription levels and digests; full-text search; moderation queue with flags, approval, silence/suspend/ban, IP blocks; spam defence (new-user rate limits, trust levels, Akismet/honeypot); edit history + wiki posts; pin/lock/close/timers; server-rendered or crawler-friendly pages with sitemap/robots; user profiles, avatars, GDPR export/anonymise/delete; RSS; backups/restore; responsive mobile UI; admin dashboard.

Evidence on effort: no published 2024–2026 engineering post-mortem with hours or headcount for "custom forum vs Discourse" was found **[not found]**. Indirect evidence: Godot replaced its Question2Answer site because it "was infrequently updated and had some security issues … leading to problems like bot registrations and spam which took a lot of manual effort to manage", importing 120k of 150k items after dropping 20% spam ([Godot, Dec 8 2023](https://godotengine.org/article/introducing-new-forum/)); OSM chose self-hosted Discourse integrated with OSM accounts ([OSM blog, Mar 21 2022](https://blog.openstreetmap.org/2022/03/21/a-new-discussion-forum-for-osm)); Lobsters' own README: "the hard part about starting an online community is not the codebase" ([repo](https://github.com/lobsters/lobsters)). Discourse's ~70 importers and monthly security cadence are a proxy for how much surface a forum accumulates.

## Section 5 — Forum vs Discord for small maker/art communities

- **Aftermath, May 12 2025** (Luke Plunkett): DECA Games shut the *Star Trek Online* / *Neverwinter* / *Champions Online* forums for Discord; forums are "an everlasting repository of knowledge", Discord "a river that never stops running" ([article](https://aftermath.site/discord-forums-move-champions-neverwinter-star-trek-support-faq/)).
- **Discourse blog, Oct 21 2025** (JA Westenberg, vendor-hosted so biased): chose Discourse over a half-configured Discord for ownership, public moderation logs, trust levels, searchability ([post](https://blog.discourse.org/2025/10/on-building-communities-in-public-why-i-chose-discourse-over-discord/)).
- **Godot** kept Discord and *added* a Discourse forum with shared SSO (Dec 2023, above). **Aseprite** (pixel-art editor) runs both a Discourse forum ([community.aseprite.org](https://community.aseprite.org/t/welcome-to-aseprite-community/8)) and an official Discord. **Lospec** (pixel-art community) is Discord-centric ([Lospec communities article](https://lospec.com/articles/pixel-art-communities/)).
- HN "Ask HN: Why Discord instead of a public forum?" (Jun 2023) and the existence of Discord-to-web indexers (Answer Overflow, dforum, index-cord, Disforum) document the discoverability gap ([HN](https://news.ycombinator.com/item?id=36390647), [Answer Overflow Show HN](https://news.ycombinator.com/item?id=36383773)).
- **No quantitative retention data** for small art communities was found **[not found]**; the evidence is qualitative and mostly about search/archival.

## Bottom line for the stated constraints (factual, not a recommendation)

- Only three candidates accept a non-OIDC SSO from the existing JWT stack out of the box: **Discourse** (DiscourseConnect, official), **NodeBB** (JWT-cookie session-sharing plugin by a co-founder), **Talkyard** (upsert-user API, one-developer project). **Zulip** also takes a JWT login but is chat and not search-indexed. Flarum needs a community extension; Misago/Lemmy/Answer need you to become an OAuth2/OIDC provider.
- RAM on the shared box: NodeBB ~0.5–1 GB, Flarum/phpBB/MyBB less, Discourse ~1.5–2 GB steady plus swap for rebuilds, Talkyard/Mbin ≥2–6 GB.
- Zero-cost hosted paths that keep the domain/SSO: none. Discourse Free has no custom domain or DiscourseConnect; NodeBB's free Starter for GPLv3 projects lacks SSO; Communiteq Starter at $20/mo is the cheapest hosted Discourse with SSO + own hostname.
